# UPPER BOUNDS ARE LOAD-BEARING. fastapi and mcp were lower-bound-only until CI
# first ran a clean install (2026-08-03) and immediately failed 182 tests on
# both Linux and Windows. A clean `pip install -r requirements.txt` resolved
# majors far ahead of what dev and production actually ran, and ADMZ did not
# work on them. PR #222 pinned both; #223 is removing the pins one at a time.
#
# fastapi: RESOLVED (#223, Starlette half). ADMZ's 70 `TemplateResponse(name,
#   context)` call sites were migrated to the Starlette 1.x
#   `TemplateResponse(request, name, context)` signature, and the
#   route-inventory tests were ported off the flat-`app.routes` assumption that
#   FastAPI >= 0.130 broke (see tests/route_inventory.py).
#
#   The floor deliberately stays low: both the migrated call signature and the
#   route-inventory helper work on the old AND new router layouts, so
#   production's existing 0.129 venv stays in spec while a clean install now
#   correctly resolves 0.141+. The `<1` cap is the lesson of #222 kept rather
#   than discarded — bounded at the next major boundary, not unbounded again.
#
# mcp: RESOLVED (#223, mcp half). The 1.x low-level decorators
#   `@server.list_tools()` / `@server.call_tool()` are gone; handlers are now
#   registered with `add_request_handler(method, params_type, handler)`, take
#   `(ctx, params)`, and return `ListToolsResult` / `CallToolResult`.
#   `Tool.inputSchema` is now `Tool.input_schema` — camelCase survives only as
#   the pydantic serialization *alias*, so `Tool(inputSchema=...)` still
#   constructs (all 35 inline tool definitions were untouched) but attribute
#   reads had to move.
#
#   The floor is 2.0 rather than something lower: `mcp.types` is a shim over the
#   split-out `mcp-types` package from 2.0 onward, and the handler-registration
#   API this code now calls does not exist in 1.x. Unlike fastapi above, there is
#   no signature that satisfies both majors, so this one really is a floor. The
#   `<3` cap keeps #222's lesson rather than discarding it.
#
#   Note for whoever raises this next: 2.0 also dropped the SDK-side
#   `jsonschema.validate(arguments, tool.inputSchema)` that 1.x ran before every
#   tool dispatch. admz/mcp/server.py now performs that check itself — do not
#   delete it assuming the SDK still does it.
