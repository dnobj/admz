Detect rule firings (webhook)

ACS exposes no API that reports when an action rule fires. The supported way is to add a one-time “Send HTTP Notification” action to each rule you want to track, pointing at this URL. ADMZ then shows the firing on the Activity feed (with the rule name) and runs any matching ACS detections — in real time.

How to configure it in ACS
In ACS: Configuration → Recordings and events → Action rules → (your rule) → add an action → “Send HTTP Notification”. Set the URL above; under credentials use any username and paste the token as the password (HTTP Basic). For the message body, send JSON like: 
{"rule":"<rule name>","camera":"<device name>","time":"<timestamp>"}
(Use ACS’s notification variables for the values. Only the body is up to you — ADMZ accepts rule/ruleName/name, camera/source, message.)

Detect rule firings (Firebird, no rule edit)

Reads a read-only copy of ACS's embedded config + log databases on this host. Catches named action-rule firings without modifying any rule — but only firings ACS logs as alarms, and it uses ACS's unsupported internal DB. Best paired with the webhook above (webhook = real-time + every rule; Firebird = zero-touch inventory + alarm firings).
